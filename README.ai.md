# Zemer — AI workspace notes

This is a Rust workspace for a clean-room, cross-platform music format library. Target Windows and Linux. Use published specifications and original tests; do not copy proprietary or GPL implementation code.

## Workspace crates

- [`zemer-core`](crates/core/): shared PCM/DSD decoder and encoder interfaces; `transcode_dsd` preserves source metadata, while `transcode_dsd_with_metadata` accepts format-mapped tags; re-exports metadata and audio buffer types.
- [`zemer-cue`](crates/cue/) (Rust crate `cue`): clean-room WAVE/AUDIO CUE parser, writer, and checked sector/sample-frame conversion; UTF-8/Shift-JIS input is capped at 16 MiB.
- [`zemer-dsd`](crates/dsd/): reusable native DSD stream specification and packed octet buffers.
- [`zemer-dst`](crates/dst/): reusable clean-room DST frame decoder and first-order encoder for DSD64/128/256 profiles.
- [`zemer-dsdiff`](crates/dsdiff/) (Rust crate `dsdiff`): streams raw DSD across the full 1–65,535-channel DSDIFF `CHNL` range and compressed DST (up to 64 channels at DSD64/128/256, including optional frame CRC checks), and writes raw DSD or DST frames compressed with a clean-room first-order predictor when useful, falling back to valid processing-mode-0 bypass frames. CLI output selects compressed DST with `--format dsdiff_dst`. It supports title, artist, general/typed COMT comments, channel IDs, and typed DIIN/MARK records. Same-format CLI conversion retains typed comments and markers. Cross-container CLI conversion keeps DSDIFF-representable title, artist, comment, and channel-ID fields and drops source-only tags the target cannot encode. Metadata edits preserve audio and unchanged/unknown chunks. All three complete 300-frame `DST_02_02` vectors pass bit-exactly; the first 10 frames of every available ISO DST vector also pass.
- [`zemer-dsf`](crates/dsf/): DSF 1.01 raw DSD decoder/encoder, supporting both one-bit and eight-bit storage order; reads common uncompressed ID3v2.2/v2.3/v2.4 text and APIC/PIC pictures and writes ID3v2.4 text and pictures. Its format-specific API and DSF-to-DSF CLI conversion preserve complete bounded raw ID3 tags; metadata edits retain opaque frames and copy DSD bytes unchanged, including tags that use tag-level unsynchronization or extended headers. DSF↔WavPack native DSD CLI conversion preserves shared text and pictures; DSDIFF conversion carries only fields representable by DSDIFF. ID3v2.2 tags with the reserved compression flag are ignored as required by that tag version.
- [`zemer-flac`](crates/flac/) (Rust crate `flac`): native and Ogg-FLAC integer-PCM encoders, native/Ogg-FLAC decoders, native seekable decoding, Ogg-FLAC restart-and-scan seeking, native and Ogg-FLAC Vorbis-comment rewriting, and preserved typed metadata blocks. Ogg decoding accepts the current mapping and the tested pre-1.1.1 legacy packet layout; encoding and metadata edits write the current mapping. Ogg metadata edits preserve encoded audio packets and update only the first chained link. Chained Ogg-FLAC links may use different audio specifications; `spec()` and each returned PCM block report the active link's specification. CLI inspect and convert only summarize chains whose links share one audio specification.
- [`zemer-g711`](crates/g711/) (Rust crate `g711`): shared G.711 A-law/μ-law sample encoder and decoder used by WAVE and AIFF-C.
- [`zemer-ima-adpcm`](crates/ima-adpcm/): shared clean-room IMA ADPCM predictor and Apple IMA4 packet codec used by WAVE, AIFC, and CAF.
- [`zemer-ms-adpcm`](crates/ms-adpcm/): shared clean-room Microsoft ADPCM block decoder and encoder; decode accepts bounded format-defined coefficient tables, while encode uses the standard seven predictors.
- [`zemer-g726`](crates/g726/) (Rust crate `g726`): clean-room interleaved PCM encoder and decoder for 16/24/32/40 kbit/s with MSB-first and LSB-first packing. The encoder matches external SpanDSP packed-codeword oracles at all four rates; the decoder matches all 80 official reset/homing, normal/overload, i-input, and cross-law rate cases, plus the McGill 40-kbit/s AIFC sample for all 294 declared frames.
- [`zemer-dwvw`](crates/dwvw/): clean-room DWVW channel encoder and decoder, independently checked against published AIFC example PCM and a libsndfile-generated test payload.
- [`zemer-metadata`](crates/metadata/): format-independent tags and embedded-picture values shared by audio formats; native/Ogg-FLAC PICTURE blocks and Ogg Vorbis `METADATA_BLOCK_PICTURE` comments map to the shared picture API.
- [`zemer-id3`](crates/id3/): bounded ID3v2 text and APIC/PIC picture parsing, encoding, and metadata rewriting shared by DSF and AIFF/AIFC.
- [`zemer-iso9660`](crates/iso9660/): clean-room ISO 9660 image inspection and safe single-volume extraction, including Joliet names.
- [`zemer-ogg`](crates/ogg/): bounded Ogg page/packet reader and writer reused by Ogg-FLAC.
- [`zemer-opus`](crates/opus/): clean-room Ogg Opus stream reading with `OpusHead`/bounded `OpusTags` validation and granule-aware packet access, regular and self-delimited packet framing with multistream packet splitting, TOC mode/bandwidth mapping, range-decoder foundations, CELT frame-header and energy decoding, allocation/reallocation, fine-energy/shape splitting, priority-based final energy bits, bounded PVQ pulse allocation/codeword indexing/normalization, exact integer codebook-cost rounding, mono unsplit-band normalized PVQ shape decoding, CELT spreading rotations, TF-resolution parameter decoding, and mono PVQ split-angle resolution/probability decoding; Ogg Opus decoding remains in progress and unsupported pending recursive CELT splits and gain/bit redistribution, stereo, TF transforms/PCM, bit-exact pulse allocation validation, SILK/hybrid decoding, and RFC 8251 validation.
- [`zemer-vorbis`](crates/vorbis/): clean-room Vorbis I Float32 decoder and experimental encoders, including Floor 0/1, residue 0/1/2, inverse coupling, inverse MDCT, windowing, overlap-add, sequential chained links with differing specifications, terminal-granule trimming/validation, linear sample-frame seeking for seekable inputs via restart-and-scan, and first-link comment rewriting that preserves encoded packets. `METADATA_BLOCK_PICTURE` comments map through the shared embedded-picture API for decoding, encoding, and rewriting. Both encoder profiles use an adaptive 31-point Floor 1 spectral envelope; the fixed profile uses 8192-sample blocks, omits 16-bin residue partitions that quantize entirely to zero, and has a scalar residue codebook configurable from 8 to 16 bits (12-bit default). An experimental target-bitrate constructor assigns a per-audio-packet budget, accounting for Ogg page overhead, and greedily allocates quantizer precision by unweighted spectral squared-error reduction. Its effective minimum depends on sample rate and channel count because mandatory packet overhead varies by profile; targets that cannot fit are rejected. FFmpeg independently decodes two-second target-rate profiles at 1–8 channels plus 192-kHz stereo, including 5.1 at 256 and 320 kbit/s; ffprobe confirms exact stream durations, and channel-order-matched PCM has maximum per-channel RMS error below 0.0043. The fixed encoder also round-trips a one-frame 255-channel stream internally; this is a boundary check, not high-channel interoperability coverage. For the mono profile, FFmpeg 4.2.2 raw PCM export emits 1,536 padding samples unless clipped to the stream duration. On a 30-second public-domain music excerpt, Zemer's target-rate output at 65.8/130.0/194.2 kbit/s measured RMS errors of 0.00872/0.00289/0.00149 against the decoded input; near-rate-matched FFmpeg/libvorbis outputs measured 0.01950/0.00595/0.00331. These are sample-error measurements, not perceptual listening results. On a 148.2-second public-domain ambient source, Zemer at 64.254/128.307/192.359 kbit/s and FFmpeg 8.1/libvorbis at 64.145/127.827/192.354 kbit/s decoded all 6,535,620 frames; per-channel RMS errors were 0.01357/0.01438, 0.00519/0.00581, 0.00307/0.00338 for Zemer and 0.02248/0.02197, 0.00762/0.00756, 0.00425/0.00426 for libvorbis. libsndfile independently verifies the fixed encoder's five quantizer precisions and mono, stereo, 3-channel, 5.1, and 7.1 outputs. In an independent comparison, fixed-profile zero-partition omission reduced a 44.1-kHz stereo sample from 73,413 to 35,753 bytes (51.3%) with bit-identical libsndfile-decoded Float32 PCM. The decoder matches independent PCM oracles for libvorbisenc streams at mono 8 kHz, stereo 44.1 kHz, three-channel 32 kHz, 5.1 48 kHz, seven-channel 44.1 kHz, and 7.1 96 kHz (12,347 frames per profile; maximum absolute error below 0.002); a libsndfile 1.2.2 192-kHz stereo stream decoded by FFmpeg 4.2.2 (12,347 frames); and two further libVorbis 1.3.7 `oggenc` streams with 4 channels at 22.05 kHz and 5 channels at 44.1 kHz (18,211 and 30,017 frames), matched to libsndfile oracles; a full-length CC0 176.587-second Für Elise recording encoded by Xiph libVorbis I 1.3.3 matches an FFmpeg-derived 16-bit FLAC PCM oracle across all 7,787,476 frames; a public-domain 3.174-second drum-roll/cymbal sting encoded by Xiph libVorbis I 20040629 matches FFmpeg 8.1 PCM for all 139,990 frames; a 148.2-second worldwide public-domain ambient song encoded by Xiph libVorbis I 20070622 matches all 6,535,620 frames against an FFmpeg 8.1-derived half-gain 16-bit FLAC PCM oracle; a 193-second CC BY 4.0 Commons piano stream matches an FFmpeg-derived 24-bit FLAC oracle sample-by-sample; and 19 standalone external Xiph vectors: `1.0-test.ogg`, `1.0.1-test.ogg`, `48k-mono.ogg`, `rc3-test.ogg`, `beta3-test.ogg`, `beta4-test.ogg`, `bimS-silence.ogg`, `rc1-test.ogg`, `rc2-test.ogg`, `mono.ogg`, `sleepzor.ogg`, `highrate-test.ogg`, `moog.ogg`, `rc2-test2.ogg`, `out-of-spec-blocksize.ogg`, and four Floor 0 LSP vectors. Both official Xiph chained vectors also pass per-link PCM comparisons while changing channel count between links. Xiph `test-short.ogg`, the first link of `chain-test3.ogg`, and `combustion.ogg` and `make.ogg` are excluded as exact PCM oracles because setup and audio packets share a page contrary to the mapping's fresh-page rule; independent decoders discard different leading portions. `one-entry-codebook-test.ogg` is truncated in its final page, `singlemap-test.ogg` lacks an EOS page, and `unused-mode-test.ogg` reaches an out-of-range audio-mode index and is rejected. The CLI can inspect, convert to Vorbis with optional `--bitrate` in kbit/s, and edit Ogg Vorbis comments; conversion maps recognized WAVE speaker masks into Vorbis channel order and rejects unrecognized masks. Malformed Ogg truncation and packet-concealment checks pass; perceptual evaluation and wider bitstream conformance remain open, so the format is not advertised as supported.
- [`zemer-pcm`](crates/pcm/): reusable PCM sample types and sample-format conversion.
- [`zemer-resample`](crates/resample/): streaming Float64-intermediate windowed-sinc sample-rate conversion with channel/speaker-mask preservation and a 64:1 maximum rate ratio.
- [`zemer-raw-pcm`](crates/raw-pcm/): headerless PCM reader/writer for explicit U8, signed 16/24/32-bit, and IEEE float32/64 byte-order profiles; raw input requires caller-supplied rate and channel count.
- [`zemer-wav`](crates/wav/) (Rust crate `wav`): RIFF/WAVE library crate with PCM/float/G.711 read/write, 1–8-channel IMA ADPCM and mono/stereo Microsoft ADPCM decode/encode. Multichannel IMA output uses WAVE_FORMAT_EXTENSIBLE and its compressed-block sample-count field; independent three-channel encode/decode vectors are sample-exact. The crate also supports required `fmt ` extensions and `fact` sample counts for non-PCM output, all 23 registered RIFF INFO text fields, RF64, `LIST/wavl`, and typed `bext`, `cue `, and `smpl` chunk read/write. Bounded ID3v2 metadata and APIC/PIC pictures read from `id3 `/`ID3 ` compatibility chunks; writes lowercase `id3 ` chunks and preserves opaque ID3 frames during metadata edits. This is an ecosystem convention, not a formal WAVE artwork field. `rewrite_metadata_with_bext` updates or adds Broadcast Wave metadata while preserving audio and other chunks. ADPCM decoding validates block geometry and trims padded frames using `fact`; Microsoft ADPCM coefficient tables are bounded by count and WAVE-format size. FFmpeg 7.0.2 verifies mono/stereo Microsoft ADPCM interoperability in both directions. INFO honors common `CSET` code pages (default 1004); new metadata declares UTF-8, while edits preserve the existing code page and unchanged fields byte-for-byte.
- [`zemer-aiff`](crates/aiff/) (Rust crate `aiff`): AIFF classic integer PCM at 1–32 valid bits and AIFC big-endian/little-endian (`sowt`) PCM, float, G.711, IMA4, DWVW, and G.726 streaming support. Apple IMA4 encode/decode supports mono and stereo; ignored FFmpeg oracles check both generated profiles. The `sowt` writer has byte-layout and round-trip coverage at 8/16/24/32 bits, with FFmpeg interop at 16 bits. AIFC also reads channel-sequential DWVW at 2–32 bits and G.726 at 8 kHz in all four standard rates. A published 12-bit minimum-delta vector decodes through mono and stereo AIFC containers. Reads/writes native text and typed `COMT`/`MARK`/`INST`, opaque `SAXL`, raw 24-byte `AESD`, and the non-standard ID3 compatibility chunk. SAXL data is retained but not applied to codec seeking. Legacy AIFC G.722/G.728/GSM remain gated on IPR review; ACE/MACE need complete clean-room algorithms and independent vectors. Broader corpus coverage and general full-container stereo DWVW interoperability remain open.
- [`zemer-au`](crates/au/) (Rust crate `au`): Sun/NeXT AU streaming signed PCM 8/16/24/32-bit, IEEE float32/64, G.711 A-law/μ-law, and mono 8 kHz G.721/G.723 3-bit/5-bit ADPCM reader/writer; bounded raw annotation preservation and COMMENT metadata rewriting. G.721/G.723 reuse `zemer-g726` at 32/24/40 kbit/s; G.721 and G.723 use low-bit-first packing, confirmed by Sun's original G.72x decoder. On 4,096 codewords per rate, G.723 PCM matches an isolated ITU-T G.191 reconstructed-signal reference after the G.726 Annex A limiter; FFmpeg/libsndfile produce differing PCM on these vectors. AU remains Partial; see `ROADMAP.md` for remaining compatibility work. G.723 encoding requires complete eight-sample groups. All eight standard McGill PCM/float/G.711 profiles match FFmpeg sample-for-sample, and both McGill malformed AU samples are rejected. External samples are not bundled; see `tests/fixtures/README.md`.
- [`zemer-caf`](crates/caf/) (Rust crate `caf`): CAF v1 signed PCM 16/24/32-bit and IEEE float32/64 in either byte order (packed/unpacked 24-bit), G.711 A/μ-law, Apple IMA4, UTF-8 `info` metadata, and audio-preserving metadata rewrites. A generated FFmpeg 8.1 big-endian signed-16 vector is checked sample-for-sample. Multichannel files require a supported speaker bitmap. Only integral rates representable by shared `AudioSpec` are accepted; AAC/ALAC/MACE and custom channel descriptions remain unsupported.
- [`zemer-wavpack`](crates/wavpack/) (Rust crate `wavpack`): PCM/float32, hybrid `.wvc`, and native DSD decoding; lossless integer PCM encoding for 1–32 channels at 8/16/24/32 bits; standard-bitrate integer PCM hybrid `.wv`+`.wvc` encoding; bit-exact float32 encoding through uncompressed WVX; raw native DSD encoding for 1–32 channels; APEv2 text tags and front/back cover art. Cover images support JPEG, PNG, GIF, BMP, WebP, and TIFF; unrelated binary items are preserved.
- [`zemer`](crates/zemer/): CLI package and executable for inspection, WAVE/AIFF/AU/CAF/FLAC/Ogg Vorbis/WavPack/raw PCM conversion, explicit raw PCM parameters, WAVE IMA and Microsoft ADPCM, WAVE/AIFC/AU/CAF G.711, AIFC/CAF IMA4, AIFC `sowt`, G.726, and DWVW output, DSF/DSDIFF/native DSD WavPack transcoding, format metadata editing, CUE/WAV workflows, and ISO 9660 inspection/extraction. CLI code is organized under `crates/zemer/src/cli/` by audio conversion, metadata editing, and reporting.
- [`tests/`](tests/): workspace-level integration tests; codec parser unit tests stay with their format crate. `opus_rfc8251_vectors.rs` is an optional ignored packet-framing baseline that reads the external RFC corpus from `ZEMER_OPUS_TESTVECTORS`.

Ogg-FLAC decoding interprets granules as zero-based last-sample indexes and
verifies each link's terminal position against its decoded sample count and
initial offset, including when STREAMINFO total samples are unknown. It trims
trailing samples from the final decoded block when required. Chained links may
have different audio specifications; metadata
comes from the first link.
Seekable sources can restart at their initial Ogg offset and scan forward to a
target sample; this path is linear. The optional official CC0 FLAC testbench
also round-trips accepted cases through the Ogg-FLAC encoder and decoder.
Independent FFmpeg-generated Ogg-FLAC PCM oracles cover eight synthetic
profiles across channel counts 1–8, up to 7.1 24-bit at 192 kHz, including large
packets continued across Ogg pages. A separate sparse 7.1 profile verifies full
PCM and seeking immediately before and after silent-channel run transitions.
Two synthetic Ogg-FLAC files from the
libFLAC 1.4.3 reference encoder add 8-bit mono and 32-bit 7.1 coverage. The
official CC0 native-FLAC corpus also
round-trips through Zemer's Ogg-FLAC encoder and decoder. Sixteen current-mapping
real-source vectors, including nine bundled CC0/public-domain/CC BY-SA Commons or
NASA recordings, have been checked against known PCM oracles; two pre-1.1.1
legacy samples were compared with libFLAC PCM oracles. A real chained-link test
rewrites first-link metadata, verifies PCM across independent 44.1- and 48-kHz
profiles, seeks immediately before and at the link boundary, accepts exact EOF,
and rejects seeks beyond EOF. Optional ignored tests use external temporary
files. Broader Ogg-FLAC source and encoder coverage remains open; do not claim
broad corpus conformance.

AIFF and AIFC PCM/float/G.711/IMA4/DWVW/G.726 support is in `crates/aiff/`;
the reader honors `SSND.offset` and accepts nonzero `SSND.blockSize` alignment.
G.726 decode accepts the recognized bitrate hint or an explicit rate; the library
encoder takes an explicit rate and writes that hint. G.722, G.728, and GSM
remain unintegrated pending IPR review; ACE/MACE lack complete clean-room
algorithm descriptions and independent test vectors. Metadata-only rewrites
preserve unknown chunks and the encoded audio bytes; transcodes retain mapped
metadata only. The optional
ignored `tests/aiff_interop.rs` test compares the McGill/AFsp 12-bit AIFF and
AIFC samples with independent FFmpeg PCM oracles; the sample files and oracles
are temporary inputs, not bundled fixtures. A second optional corpus test
checks six McGill AIFC edge cases; the reader tolerates a single missing final
odd-chunk pad byte only when the file and chunk bounds prove that exact case.
An additional external corpus check covers seven CCRMA AIFF/AIFC files and the
underreported COMM size in McGill's `digit0v0.aiff` sample.

The WAVE reader handles top-level PCM/G.711 `data` and ordered `LIST/wavl`
`data`/`slnt` segments in RIFF and RF64, and streams IMA ADPCM blocks with
`fact`-count trimming. Silence segments hold the previous interleaved frame;
initial silence uses neutral sample codes. The reader limits files to one
million retained audio segments and supported INFO metadata to 16 MiB total,
65,536 values, and 1 MiB per value. Typed `bext`, `cue `, and `smpl` chunks
are each limited to 16 MiB. The writer still emits one ordinary contiguous
`data` chunk.

## Other repository paths

- `crates/pcm/src/`: shared PCM types and per-representation modules (`u8.rs`, `i16.rs`, `i24.rs`, `i32.rs`, `f32.rs`, `f64.rs`).
- `crates/resample/src/`: format-independent streaming sample-rate conversion.
- `ROADMAP.md`: public plan for codecs, conversion, metadata, and disc-image workflows.
- `docs-internal/FORMAT_SUPPORT.md`: local-only implementation support notes; ignored by Git.
- `docs-internal/REFERENCES.md`: local-only research links and regression notes; ignored by Git.
- `docs`: user-facing Sphinx documentation built on Read the Docs, with `conf.py` at the source root.

`README.md` lists only implemented and tested formats and workflows; planned formats belong in `ROADMAP.md`. The CLI can edit WAVE RIFF INFO and BWF `bext` fields (including UMID and reserved bytes as fixed-length hex), AIFF/AIFC NAME/AUTH/(c)/ANNO and ID3 text, AU COMMENT annotations, CAF UTF-8 `info` tags, DSF ID3 text, DSDIFF text/comments, native or Ogg-FLAC Vorbis comments, Ogg Vorbis comments, and WavPack APEv2 text with `zemer metadata edit`; these rewrite metadata without decoding or re-encoding audio, preserving unchanged WAVE INFO and BWF fields byte-for-byte, raw AU annotations when unchanged, CAF audio packets, ID3 pictures and opaque frames, unknown AIFF/DSDIFF chunks, and WavPack cover art and unrelated non-text items. The WavPack library maps JPEG/PNG/GIF/BMP/WebP/TIFF front/back cover items through shared `Metadata::pictures()`. Ogg-FLAC metadata edits preserve encoded FLAC packets and update the first chained link only. `FlacDecoder::metadata_blocks()` retains raw payloads, FLAC metadata-block accessors expose typed PICTURE/CUESHEET/SEEKTABLE/APPLICATION data, and native and Ogg-FLAC PICTURE blocks populate the shared `Metadata::pictures()` collection.

Keep each new format in a separate crate depending on `zemer-core`. Keep format parsing and metadata mappings inside that format crate, with the common tag model in `zemer-metadata`. Shared sample types and sample-format conversion belong in `zemer-pcm`; sample-rate conversion belongs in `zemer-resample`; decoder/encoder interfaces belong in `zemer-core`. Whole-format conversion should decode to `PcmBuffer`, apply only explicitly requested audio transforms, and encode through the target format crate; `transcode` finalizes the encoder after successful copying. Avoid global registries until callers need them.

CLI conversion preserves a floating-point input for formats that support it. Float input converted to native FLAC, Ogg-FLAC, or AIFF uses 24-bit integer PCM; AIFC can preserve IEEE float samples.

The Ogg reader exposes the EOS granule even when the terminal page has no packets. Vorbis holds the final overlap-add chunk until that granule is known, then trims it; comment rewriting moves the terminal granule onto the final packet page. Comment packets may continue across Ogg pages; rewriting a 70 KiB lyrics field preserves all encoded audio packets. CLI metadata edits retain unmodified repeated comments, including `METADATA_BLOCK_PICTURE`, while replacing or removing only requested keys.

Vorbis header validation requires the setup packet to end its Ogg page, so the first audio packet begins on a fresh page as required by the mapping. A synthetic page-sharing regression verifies that non-compliant streams are rejected.

Vorbis decoding also uses the granule on the page completing the second audio packet to trim pre-zero samples or account for a positive start position. Non-zero offsets require that packet to end its page, so the third packet begins fresh; terminal granules remain relative to the starting position, and standard pages with no granule do not change it.

The public Vorbis decoder accepts short reads and retries interrupted reads from its input source; an end-to-end regression compares its PCM with the ordinary reader path.

The Vorbis integration tests flip every bit in an independent real setup header and assert parsing never panics. A generated Vorbis stream is also rejected at every truncation point in its identification page; later pages have representative truncation checks.

Checked-in Vorbis input fixtures include Xiph/libVorbis and two independent Rust encoder outputs. `oxideav-vorbis 0.0.12` coverage includes stereo 44.1-kHz music and a synthetic six-channel 48-kHz transient profile, each paired with a full libsndfile 1.2.2 Float32 oracle; both external encoders are test-fixture sources only and are not Zemer dependencies.

For later Ogg pages, the decoder checks each owned granule against the decoded PCM endpoint when a following packet arrives. It defers the most recent page's check so a final audio packet followed by a nil EOS page can still use the EOS granule to trim its overlap tail.

Before adding a dependency, record its license and platform/build requirements. Run tests on Linux through `server5`; keep Windows and Linux CI jobs in sync. See `README.md` for current support and public usage.
